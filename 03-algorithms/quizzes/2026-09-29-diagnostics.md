## 1. Big O, сложность базовых операций
**Ответ ученика:** Big O — время выполнения операции, оценивают чтобы выбрать быстрый алгоритм.
arr[i] — O(n), includes — O(n), set.has — O(n), sort — O(n²) худший / O(n) лучший, вложенные циклы — O(n²).
**Разбор:** Big O — не время, а скорость роста времени/памяти при росте n (константы отбрасываются, обычно худший случай).
arr[i] — O(1) (адрес вычисляется: начало + i × размер); set.has — O(1) в среднем (хеш-таблица);
sort — TimSort в V8: O(n log n) худший, O(n) лучший. includes и вложенные циклы — верно.
**Оценка:** 1–2 — не знает O(1) доступа по индексу и в Set/Map.

## 2. hasDuplicates: O(n²) → O(n)
**Ответ ученика:** O(n²); идея «запоминать увиденное, платим памятью» — сам. После наводящих вопросов написал:
```js
function hasDuplicates(arr) {
  const uniqueEls = new Set();
  for (let i = 0; i < arr.length; i++) {
    if (uniqueEls.has(arr[i])) return true
    else uniqueEls.add(arr[i])
  }
  return false
}
```
**Разбор:** код верный, порядок has → add верный. Лишний else после return; for...of чище.
Альтернатива `new Set(arr).size !== arr.length` — тоже O(n), но без раннего выхода.
Сложность по памяти не знал: объяснено — O(1) у двух циклов, O(n) у Set. Trade-off время/память.
Первый код выдал псевдокодом — на live-coding нужно сразу писать рабочий код.
**Оценка:** 2 — идея и код верные, space complexity не знал.

## 3. Поиск в отсортированном массиве из 1 000 000 элементов
**Ответ ученика:** не includes (O(n)); проверить границы; брать середину и сужать диапазон пополам; O(log n).
**Разбор:** это бинарный поиск — называть термин. Проверку границ сформулировал наоборот
(правильно: x < arr[0] или x > arr[last] → false). Выходить сразу при arr[mid] === x.
Не назвал число шагов: log₂(10⁶) ≈ 20. Работает только на отсортированных данных
(сортировка ради одного поиска — O(n log n), хуже includes).
**Оценка:** 3 — идея и сложность верные; код бинарного поиска не проверялся.

## 4. Two Sum (2026-09-30, в процессе)
Дан массив `nums` и `target`. Вернуть индексы двух элементов с суммой target. Решение ровно одно, элемент нельзя
использовать дважды.
```js
twoSum([2, 7, 11, 15], 9)  // [0, 1]
twoSum([3, 2, 4], 6)       // [1, 2]
twoSum([3, 3], 6)          // [0, 1]
```
1. Очевидное решение и его сложность? 2. Решение за O(n) (hash map). 3. Сложность по времени и памяти.

**Ответ ученика (попытка 1):** перебор O(n²) / O(1) — сложность верно, но в коде баг: `j` начинается с 0 →
`nums[i] + nums[i]`, элемент используется дважды (`twoSum([3,2,4], 6)` → `[0, 0]`).
Идея O(n): Map, ключ — число, значение — `nums[i] - target` (знак перепутан); на каждой итерации проверять,
совпадает ли текущее число с одним из значений Map.
**Разбор:** поиск по значениям Map — O(n), O(1) только по ключу. Нужно: ключ = число, значение = индекс,
проверка `map.has(target - num)`. Код O(n)-решения не написан — снова идея вместо кода.
Сложность O(n) / O(n) названа верно.
**Попытка 2 (в playground/twoSum.js, с наводящими вопросами):** перебор исправил сам (`j = i + 1`).
O(n)-версию сначала написал, смешав два варианта (set(complement) + has(complement)) — тесты упали,
`[3,3]` прошёл случайно. После трассировки по шагам исправил на классический вариант:
```js
function twoSumFast(nums, target) {
  const numsMap = new Map()
  for (let i = 0; i < nums.length; i++) {
    const oppositeNum = target - nums[i]
    if (numsMap.has(oppositeNum)) return [numsMap.get(oppositeNum), i]
    else numsMap.set(nums[i], i)
  }
  return []
}
```
Все тесты + доп. кейсы (отрицательные, нули) проходят. Мелочи: лишний `else` после `return` (второй раз),
имя `complement` вместо `oppositeNum`.
**Оценка:** хеш-таблицы — 2 (решил с подсказками; понял «быстро проверяем только ключи»). Без подсказок → 3.

## 5. Два указателя: Two Sum на отсортированном массиве (2026-09-30, ⏳ В ПРОЦЕССЕ)
Условие и тесты — `playground/twoSumSorted.js`. O(n) по времени, O(1) по памяти, `null` если пары нет.
**Рассуждение ученика:** сумма > target → двигать правый влево, < target → левый вправо — верно.
Сам ответил: правый указатель не возвращается к концу (O(n)); стоп — когда указатели встретились.
**Попытка кода 1:** `for` по левому + `while (left + right > target)` внутри. Баги:
- `right` — значение, прочитанное до цикла, а уменьшается только `rightIndex` → **бесконечный цикл** (вкладка зависла);
- проверка `=== target` внутри `while (... > target)` никогда не сработает;
- `left === right` сравнивает значения, а не индексы (сломается на `[3, 3]`);
- лишний `for` — хватает одного `while (left < right)`.
Дан каркас с `let left = 0, right = nums.length - 1; while (left < right) { const sum = ... }`.
