## 1. Big O, сложность базовых операций
**Ответ ученика:** Big O — время выполнения операции, оценивают чтобы выбрать быстрый алгоритм.
arr[i] — O(n), includes — O(n), set.has — O(n), sort — O(n²) худший / O(n) лучший, вложенные циклы — O(n²).
**Разбор:** Big O — не время, а скорость роста времени/памяти при росте n (константы отбрасываются, обычно худший случай).
arr[i] — O(1) (адрес вычисляется: начало + i × размер); set.has — O(1) в среднем (хеш-таблица);
sort — TimSort в V8: O(n log n) худший, O(n) лучший. includes и вложенные циклы — верно.
**Оценка:** 1–2 — не знает O(1) доступа по индексу и в Set/Map.

## 2. hasDuplicates: O(n²) → O(n)
**Ответ ученика:** O(n²); идея «запоминать увиденное, платим памятью» — сам. После наводящих вопросов написал:
```js
function hasDuplicates(arr) {
  const uniqueEls = new Set();
  for (let i = 0; i < arr.length; i++) {
    if (uniqueEls.has(arr[i])) return true
    else uniqueEls.add(arr[i])
  }
  return false
}
```
**Разбор:** код верный, порядок has → add верный. Лишний else после return; for...of чище.
Альтернатива `new Set(arr).size !== arr.length` — тоже O(n), но без раннего выхода.
Сложность по памяти не знал: объяснено — O(1) у двух циклов, O(n) у Set. Trade-off время/память.
Первый код выдал псевдокодом — на live-coding нужно сразу писать рабочий код.
**Оценка:** 2 — идея и код верные, space complexity не знал.

## 3. Поиск в отсортированном массиве из 1 000 000 элементов
**Ответ ученика:** не includes (O(n)); проверить границы; брать середину и сужать диапазон пополам; O(log n).
**Разбор:** это бинарный поиск — называть термин. Проверку границ сформулировал наоборот
(правильно: x < arr[0] или x > arr[last] → false). Выходить сразу при arr[mid] === x.
Не назвал число шагов: log₂(10⁶) ≈ 20. Работает только на отсортированных данных
(сортировка ради одного поиска — O(n log n), хуже includes).
**Оценка:** 3 — идея и сложность верные; код бинарного поиска не проверялся.

## 4. Two Sum — ⏳ СЛЕДУЮЩИЙ ВОПРОС (не отвечен)
Дан массив `nums` и `target`. Вернуть индексы двух элементов с суммой target. Решение ровно одно, элемент нельзя
использовать дважды.
```js
twoSum([2, 7, 11, 15], 9)  // [0, 1]
twoSum([3, 2, 4], 6)       // [1, 2]
twoSum([3, 3], 6)          // [0, 1]
```
