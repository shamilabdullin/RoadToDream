## Вопрос 1. useState и батчинг
Код: три `setCount(count + 1)` подряд + `console.log(count)` в обработчике клика.

| Вопрос | Ответ ученика | Разбор |
|---|---|---|
| Что выведет log, что на кнопке | 0 и 1; «count для каждого setCount равен 0, перерендер ещё не произошёл» | ✅ Ответ верный. Объяснение неполное: причина — замыкание на `const` снимка рендера, а не «ещё не произошёл» |
| Сколько перерендеров | 3 — «три триггера» | ❌ Один: батчинг (React 18 — автоматический, в т.ч. в setTimeout/промисах; в 17 — только React-события) |
| Как прибавить 3 | `setCount(prev => prev + 1)` ×3 | ✅ Код верный; механизм — очередь апдейтеров, применяемая за один рендер |
| log после фикса | 0 — снимок рендера | ✅ |
| `prev+1`, `count+5`, `prev+1` | 6: 0→1, затем 0+5=5 (не знает об актуальном), 5→6 | ✅ Верно разобрал очередь; `setCount(5)` — замена значения, затирает предыдущий результат |

**Оценка: useState / батчинг — 3.** Очередь обновлений и функциональные апдейты понимает уверенно (каверзный
вопрос решил верно). Батчинг не знал — узнал из разбора, проверить повторно.

## Вопрос 2. useEffect, cleanup, stale closure
Код: `setInterval(() => setSeconds(seconds + 1))` в `useEffect(..., [])` без cleanup.

| Вопрос | Ответ ученика | Разбор |
|---|---|---|
| Что на экране через 5 с | 1 — замыкание на `seconds = 0` | ✅ Нюанс: со 2-го тика рендера нет — то же значение, bail out по `Object.is` |
| Вторая ошибка | «Возможно, нужен clearInterval в return» — неуверенно | ⚠️ Исправление верное, последствия не назвал: утечка после unmount, множатся интервалы при повторном монтаже, в StrictMode (mount→unmount→mount) — 2 интервала, +2 в секунду. Cleanup вызывается и перед каждым перезапуском эффекта |
| Два способа исправить | `prev => prev + 1` + cleanup | ✅ Каноничное решение, но дал один способ |
| `[seconds]` в deps — что каждую секунду | Эффект перезапускается, интервал пересоздаётся каждую секунду | ✅ С cleanup: рендер → cleanup старого → новый интервал. По сути превращается в setTimeout; интервал сбрасывается, возможен дрейф |
| Почему функциональный апдейт лучше | Интервал создаётся один раз и работает с актуальным значением | ✅ |

**Оценка: useEffect / cleanup / stale closure — 3.** Stale closure и зависимости понимает и применяет.
Для 4: уверенно называть последствия отсутствия cleanup, поведение StrictMode, порядок cleanup → effect.

## Вопрос 3. Перерендеры и React.memo
Код: `Child` в `React.memo`, родитель передаёт `handleClick = () => ...` и `style={{ color: 'red' }}`.

| Вопрос | Ответ ученика | Разбор |
|---|---|---|
| Причины перерендера | Изменение состояния; рендер родителя (если ребёнок не в memo); изменение пропсов | ⚠️ «Изменились пропсы» — не отдельная причина (следствие рендера родителя; без memo ребёнок рендерится и при неизменных пропсах). Пропущены: контекст (`useContext`, сквозь memo), внешние сторы (`useSyncExternalStore`). Смена `key` — перемонтирование |
| Будет ли `Child render` | Да: новая функция и новый объект на каждом рендере | ✅ Поверхностное сравнение через `Object.is` |
| Исправить | 1-я версия: `const handleClick = () => useCallback(...)` и `useMemo(() => { color: 'red' }, [])` | ❌ Две ошибки: (1) хук внутри стрелки — handleClick новый каждый рендер + вызов хука вне рендера (нарушение правил хуков); (2) `{` после `=>` — тело функции, `color:` — метка, возвращается `undefined`. Нужно `() => ({ color: 'red' })`. Со 2-й попытки (после подсказок) код верный, но ошибки словами не объяснил |
| useCallback без memo у ребёнка | Бессмысленен — ребёнок рендерится всегда | ✅ Для рендера — да. Исключение: функция в зависимостях `useEffect` / другого хука |
| `style` без хуков | `const style = {...}` внутри компонента — «но пересоздастся» | ❌ Решение — вынести константу **за пределы компонента** (создаётся один раз при загрузке модуля) или CSS-класс |
| Когда memo вредит | Если нет тяжёлых вычислений — мемоизация стоит памяти | ⚠️ Общо. Не назвал: бесполезна без `React.memo` у получателя; deps меняются каждый рендер; примитивы; стоимость сравнения deps; читаемость; React Compiler (React 19) делает ручную мемоизацию в основном ненужной |

**Оценка: перерендеры — 2; useMemo / useCallback / memo — 2.** Ссылочное равенство и связку memo + useCallback понимает,
но код с двумя ошибками (одна — правила хуков, вторая — синтаксис JS), не вынес константу за компонент, миф «пропсы — причина рендера».
