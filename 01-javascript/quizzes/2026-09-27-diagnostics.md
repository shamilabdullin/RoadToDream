# Диагностика: JavaScript — 2026-09-27

## 1. Event loop — порядок вывода
```js
console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3)).then(() => console.log(4));
queueMicrotask(() => console.log(5));
(async () => { console.log(6); await null; console.log(7); })();
console.log(8);
```
**Ответ ученика:** `1 8 2 5 3 4 6 7`. Не помнит, что такое макро- и микрозадачи.
**Правильно:** `1 6 8 3 5 7 4 2`.
**Разбор ошибок:**
- тело async-функции до первого `await` выполняется синхронно → `6` сразу после `1`;
- `setTimeout` — макрозадача, выполняется последней, а не раньше промисов;
- промисы / `queueMicrotask` / продолжение после `await` — микрозадачи, выполняются сразу после синхронного кода, в порядке постановки в очередь; `.then(4)` встаёт в очередь только после выполнения `3`.
**Верно:** синхронный код выполняется первым.
**Оценка:** 1 — модель event loop отсутствует.

### 1.1 Закрепление после разбора — рекурсивные микрозадачи
```js
setTimeout(() => console.log('timeout'), 0);
function loop(n) {
  if (n === 0) return;
  Promise.resolve().then(() => { console.log('micro', n); loop(n - 1); });
}
loop(3);
```
**Ответ ученика:** micro 3, 2, 1, затем timeout; loop вызывается 4 раза, на 4-й выходит — верно.
Понял, что микрозадачи, добавленные во время разбора очереди, выполняются до следующей макрозадачи.
**Оценка:** уровень поднят до 2 (модель усвоена после объяснения, нужна практика без подсказок).

## 2. Замыкания
**Вопрос:** что такое замыкание; пример бага (stale closure) или утечки памяти в React.
**Ответ ученика:** функция запоминает своё лексическое окружение — переменные, объявленные снаружи, и имеет к ним доступ.
Пример из React привести не смог.
**Разбор:** определение в целом верное, но неточное: функция хранит *ссылку* на внешнее лексическое окружение
(живую связь, а не копию значений) места, где она *создана*, и окружение живёт, пока жива функция.
Нет связи с практикой: stale closure в useEffect/setInterval, обработчики событий, утечки через замыкания.
**Оценка:** 2 — определение знает, применение на практике не видит.

### 2.1 Закрепление — var в цикле + setTimeout; функциональный апдейт
**Ответ ученика:** выведет `0 0 0` («в каждой макрозадаче i = 0»); как исправить — не знает.
Почему `setCount(c => c + 1)` лечит stale closure — не знает.
**Правильно:** `3 3 3` — `var` имеет функциональную область видимости, переменная одна на весь цикл,
к моменту выполнения макрозадач цикл завершён и `i = 3`. Исправление: `let` (новая привязка на каждую итерацию),
IIFE / передача `i` аргументом (`setTimeout(console.log, 0, i)`).
Функциональный апдейт не читает `count` из замыкания — React передаёт актуальное состояние аргументом.
**Вывод:** ученик считает, что замыкание копирует значения, — ключевое заблуждение, закрыть в первую очередь.
Не различает var / let на уровне привязок.

## 3. Прототипы
**Вопрос:** разница `prototype` и `__proto__`; что по шагам делает `new`.
**Ответ ученика:** `__proto__` — ссылка на объект-прототип в свойствах объекта; `prototype` — объект, который является
прототипом нашего объекта; `new` создаёт объект через конструктор с переданными аргументами (пример `new String('s')`).
**Разбор:** `__proto__` — примерно верно (устаревший аксессор к скрытому `[[Prototype]]`).
`prototype` — неверно: это свойство *функции-конструктора / класса*, объект, который станет `[[Prototype]]`
экземпляров: `new F().__proto__ === F.prototype`. Шаги `new` не названы
(создать объект → связать `[[Prototype]]` с `F.prototype` → вызвать F с this → вернуть объект, если F не вернул объект).
`new String('s')` создаёт объект-обёртку (`typeof` → 'object') — антипаттерн.
**Оценка:** 1 — путает `prototype` и `[[Prototype]]`, механику `new` не знает.

## 4. Live-coding: debounce
**Ответ ученика:**
```js
function debounce(fn, ms) {
  if (debounce вызвался прекратить функцию)
  setTimeout(fn, ms)
}
```
**Разбор:** идея «отложить через setTimeout и отменять при повторном вызове» верная.
Не хватает: вернуть новую функцию; хранить id таймера в замыкании; clearTimeout; передача this и аргументов.
**Оценка:** 1 — идея есть, реализовать не может.
