## 1. Реактивность Vue 3: ref / reactive, почему не нужен сеттер
**Ответ ученика:** механизм не помнит; ref — аналог state в React; reactive — не знает; почему не нужен сеттер — не знает.
**Разбор (объяснено):** Vue 3 — Proxy: get → track (запомнить зависимость рендера/эффекта), set → trigger
(перезапустить зависящее). Само присваивание — сигнал, поэтому сеттер не нужен; нет массивов зависимостей.
React — иммутабельно, setState → перезапуск компонента + diff VDOM.
ref — обёртка { value } для любых значений (Proxy не оборачивает примитивы), .value в JS, в шаблоне разворачивается.
reactive — только объекты; нельзя переприсвоить целиком, деструктуризация теряет реактивность (toRefs).
Рекомендация — ref по умолчанию. Vue 2: Object.defineProperty не видел новые свойства и arr[i] = x → Vue.set.
**Оценка:** 1.

## Вопрос ученика: React или Vue, как выбирать, что быстрее (2026-10-01)
Объяснено: React — иммутабельность, перерисовка компонента и детей + diff всего VDOM, ручная мемоизация (или React Compiler);
Vue — Proxy-зависимости, точечные обновления, компилятор шаблонов (patch flags, вынос статики), setup один раз.
На малом/среднем проекте разница в скорости незаметна → выбирают по команде/найму, экосистеме, порогу входа, SSR-фреймворку.
Дана формулировка ответа для собеса (компромиссы + «переход — смена синтаксиса, не концепций»). Подтема 9 не проверялась.

## 3. computed vs watch / watchEffect (2026-10-01)
**Ответ ученика:** computed — как useMemo, «на основе useRef»; watch — не знает, предположил аналог useEffect.
**Разбор:** computed ≈ useMemo верно, но строится на любых реактивных источниках (ref/reactive/props), зависимости
автоматически, кешируется. watch — побочные эффекты (запрос, localStorage), watchEffect — сам собирает зависимости
и запускается сразу. Правило: значение → computed, эффект → watch. Ошибка: менять state в computed.
**Оценка:** 1 — аналогия computed верна, watch не знает.

## 4. Жизненный цикл (2026-10-01)
**Ответ ученика:** знает только onMounted — «как useEffect без массива зависимостей»; аналог cleanup не знает.
**Разбор:** onMounted ≈ useEffect(fn, []) — один раз (без массива — после каждого рендера). Тело <script setup> —
один раз, до DOM. Очистка — отдельный хук onUnmounted / onBeforeUnmount; в watch — onCleanup.
setup выполняется один раз → нет stale closures.
**Оценка:** 1.
